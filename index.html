Schema Design & ER Modelling

Designed the complete relational database from scratch — ER diagram, normalised schema, constraints, and sample data across 9 tables.

🗄️ What was built

  • Full ER diagram with all entities, attributes, and relationships
  • Normalised MySQL schema: 9 tables, all primary/foreign keys, cascades
  • Business rule constraints: FinalAmount check, expiry after manufacture, positive prices
  • Hierarchical structures: self-referencing Employee manager chain, nested Categories
  • Sample data across all tables for realistic query testing

TASK 3 · ASSIGNMENT 3

Transactions, WAL, and ACID

Added full transaction support to the B+ Tree engine with Write-Ahead Logging and Two-Phase Locking. Verified all four ACID properties with a comprehensive test suite including Locust load tests.

Transactions · 2PL · WAL

⚙️ Module A — Transaction Engine

  • WALLogger — every operation appended to wal.log before B+ Tree modification
  • LockManager — shared/exclusive table-level locks, 2-phase locking
  • SnapshotManager — per-transaction snapshots for rollback
  • TransactionManager — public API: begin, commit, rollback
  • Crash recovery by replaying WAL log

TASK 4 · ASSIGNMENT 4 · ✦ LATEST

Horizontal Database Sharding

Sharded Member, Sale, and SaleItem across 3 remote MySQL Docker nodes using MD5 hash-based routing. 6 automated tests verify routing correctness, co-location, and zero duplication.

Sharding · Distributed DB

🔀 Shard Router

Hash-based routing using MD5 on MemberID

shard_id = int(MD5(member_id)[:8], 16) % 3
  • MemberID as shard key — high cardinality, stable, query-aligned
  • Sale + SaleItem co-located with Member — no cross-shard joins
  • Graceful degradation: unreachable shard → degraded: true
MD5 HashingCo-locationFan-out

✅ Verification Tests

  • Test 1: Routing Logic — MEM001→shard1, MEM005→shard0, MEM012→shard2
  • Test 2: Single-Shard Lookup — found on exactly 1 shard
  • Test 3: Insert Routing — new member lands on correct shard
  • Test 4: Range Query — 27 sales across all 3 shards, sorted
  • Test 5: Data Distribution — all 3 shards populated
  • Test 6: No Duplication — every member on exactly 1 shard
